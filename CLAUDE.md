# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`garfex-erp-frontend`: the frontend-only workstation UI for the GARFEX ERP. React 19 + TypeScript + Vite, TanStack Router (file-based), React Aria Components, Tailwind CSS 4. Package manager is **pnpm** (Node >= 20).

The backend is a **separate, authoritative** Convex deployment (`sistema-garfex`), reached over `VITE_CONVEX_URL` (see `.env.example`). This repository must never grow a backend, persistence layer, or invented domain rules.

## Architecture

Feature-first Scope Rule / Screaming Architecture. Three top-level zones under `src/`:

- `src/app/` — routing and shell only. `main.tsx` → `AppProviders` (RouterProvider) → `routes/__root.tsx` → `AppShell`. Routes are thin: each file route renders a feature `*Entry` component and nothing else.
- `src/features/<feature>/` — one folder per feature, self-contained: screen, surfaces (dialogs), `*.types.ts`, `*.api.ts` transport adapter, local state helpers, local hooks, local CSS. Features do not import from each other.
- `src/shared/` — only genuinely transversal infrastructure: the keyboard subsystem and design-system tokens/logo. Keep it minimal; new shared abstractions must be justified.

`storybook/` is a **separate project boundary** from `src/` (`tsconfig.app.json` includes only `src`). Populated/demo data lives in `storybook/**/*.fixtures.ts` and must never be reachable from runtime code.

### Transport adapters

Convex is allowed in exactly two files: `src/features/catalog-hierarchy/catalogHierarchy.api.ts` and `catalogTypeAttributes.api.ts`. Each exports a plain `interface ...Api` over a `Transport` seam, builds `FunctionReference`s with `makeFunctionReference` from **literal** operation strings (`'catalogoAdmin/jerarquia:listarClases'`, `'catalogoAdmin/atributos:...'`), and validates every response field before returning typed data. No template strings, no computed property access, no dynamic operation names — the architecture tests assert this literally.

There is no global store and no query-cache layer. List paging/state is a hand-rolled controller (`useCatalogList.ts`) with an adapter seam; selection state is pure functions in `catalogHierarchyState.ts`.

### Keyboard First (`src/shared/keyboard/`)

The product is keyboard-driven; this subsystem is the load-bearing part of the codebase.

- `keyboardArbitration.ts` — pure `arbitrateKeyboardEvent(event, context)` deciding an owner (`editing | local | overlay | browser | global | none`) + reason + action. It **never** calls `preventDefault`. Tab/Shift+Tab always pass through to the browser; `Ctrl+N` is reserved for the browser; editing contexts (inputs, `role=textbox/searchbox/combobox/spinbutton`, contenteditable, IME composing) win over everything.
- `KeyboardController.tsx` — the **only** `document` keydown listener in the app. Do not add another one anywhere.
- `keyboardCommandRegistry.ts` — commands register themselves (`global` or `active-surface` scope) and are resolved by key + active surface + availability. Powers both dispatch and the help dialog.
- `spatialNavigation.ts` — arrow keys move focus by real geometry (scored rects), not by DOM order or roving tabindex.
- `focusRestoration.ts` — Escape restores focus to whatever opened the overlay.

The canonical contract is **section 11 of `docs/erp-first-stage-design-brief.md`** and `openspec/specs/keyboard-interaction/spec.md`. `tests/architecture/keyboardBoundaries.test.ts` asserts section 11 still contains its key clauses and that no separate keyboard doc exists — update the brief, don't create a new document.

### Architecture tests are enforcement, not documentation

`tests/architecture/*.test.ts` read source files as text and fail the build on boundary violations. Before changing runtime code, know that they forbid, among other things:

- `fetch`, `localStorage`, `sessionStorage`, Storybook imports, or fixture names anywhere in `src/`
- `convex` imports outside the two approved adapter files (in particular, none in `src/app/`)
- global stores (`zustand`, `redux`, `createStore`, `configureStore`)
- `@tanstack/react-form|react-table|react-virtual` in `src/` and in stories (also blocked by `no-restricted-imports` in `eslint.config.js`)
- extra `<Link>` destinations in `AppShell` or extra routes beyond the approved ones
- `addEventListener`/`onKeyDown`/roving-index logic inside `CatalogHierarchyScreen.tsx`

If a boundary genuinely needs to move, change the architecture test deliberately and say so — do not work around it.

## Domain model

Canonical chain: **Clase → Familia → Tipo → Recurso** (`Familia.claseRecursoId` → Clase, `Tipo.familiaRecursoId` → Familia, `Recurso.tipoRecursoId` → Tipo). Familia→Clase and Tipo→Familia are immutable.

Attributes are four distinct backend concepts — do not collapse them:

- `definicionesAtributo` — the typed attribute itself (Color, Voltaje), with `tipoDato` (`OPCION | TEXTO | NUMERO | BOOLEANO`)
- `opcionesAtributo` — allowed values, only for definitions whose `tipoDato` is `OPCION`
- `atributosRecurso` — assignment of a definition to a Familia/Tipo, with inheritance/override
- `valoresAtributoRecurso` — the concrete value a Recurso holds for an assignment

Lifecycle is revisioned: deactivate/reactivate, never physical delete.

## Workflow

- **Strict TDD is required** (`strict_tdd: true` in `openspec/config.yaml`): RED → GREEN → REFACTOR slices.
- Work is tracked with OpenSpec under `openspec/`: canonical capability specs in `openspec/specs/`, in-flight work in `openspec/changes/<change>/` (proposal → spec → design → tasks → apply-progress → verify-report), completed work moved to `openspec/changes/archive/`. `openspec/config.yaml` holds the project context, per-phase rules, and the verification commands.
- Keep authored review workload within ~400 lines per change or escalate.
- Accessibility target is **WCAG 2.2 AA**; Storybook runs `@storybook/addon-a11y` and E2E runs `@axe-core/playwright`.
- Do not install new packages without approval; use the installed stack proportionally.
- Design authority is the approved OpenPencil artifacts (`design*.op`, `recovery/`, the PNG snapshots) plus `docs/manual_identidad_garfex_ai_canonico_v2_digital.md`. Preserve them; never modify the OpenPencil recovery artifacts.
