# G8 — Proyección visible de Recursos REST

## Autorización humana y decisión aplicada

La decisión humana registrada para G8 autoriza adaptar el Maestro de Recursos al contrato REST público, sin una aceptación adicional. La pantalla muestra únicamente la proyección REST validada y no presenta sustitutos de campos legacy.

## Evidencia pública y campos mostrados

La evidencia pública en [`../api-contract-evidence.md`](../api-contract-evidence.md) documenta `GET /v1/resources` y su `ResourcePage`. Cada `Resource` requiere `id`, `identityV1`, `scope.classCode`, `scope.familyCode`, `scope.typeCode`, `naturalUnit`, `active`, `revision` y `attributes[{ code, value }]`.

La tabla de Recursos muestra:

- `identityV1` como **Identidad**;
- los tres códigos de `scope` como **Alcance**;
- `naturalUnit`, `active`, `revision` y `attributes`.

`identityV1` se muestra literalmente: no se reinterpreta como nombre ni se deriva una etiqueta equivalente.

## Impacto visible y límites

Se retiran de columnas y detalle los campos legacy no documentados: nombre, ownership, `classificationStatus` y diagnósticos. La reducción es visible y honesta: no hay estado de clasificación, titularidad, diagnóstico ni nombre de reemplazo inventado.

Aunque el contrato público documenta la ruta de descripción, la lista no solicita `/describe` por fila; por ello no introduce un patrón describe N+1. Tampoco hay llamada, selector ni fallback runtime de Convex.

## Evidencia de pruebas

La verificación de Unit 12b registrada en [`../apply-progress.md`](../apply-progress.md) confirma la proyección REST sin campos legacy con:

- `pnpm exec vitest run tests/unit/resourcesMasterScreen.test.tsx tests/unit/resourcesMasterScreenRefetch.test.tsx tests/unit/appShell.test.tsx tests/unit/useResourcesHierarchy.test.ts tests/unit/useResourcesMasterRestWindow.test.tsx tests/architecture/resourcesMasterBoundaries.test.ts` — 41 pruebas aprobadas;
- `pnpm typecheck` — aprobado;
- `pnpm test` — 64 archivos y 618 pruebas aprobadas.

## Condición para reabrir

Reabrir G8 sólo si un contrato público ampliado documenta los campos o una operación de detalle con semántica suficiente para nombre, titularidad, clasificación o diagnósticos, y el humano aprueba su impacto visible. Esa ampliación requiere DTO validado, pruebas RED→GREEN y una proyección explícita; no autoriza reinterpretar `identityV1`, usar N+1 ni restaurar Convex.
